# i18n 文案搬运规范

把界面上的中文搬进语言包时，**照这份文档做**。约 1700 条，按域分给不同的人/代理并行，
每个域只碰自己那一对语言包文件（`zh/<域>.ts` + `en/<域>.ts`），互不干扰。

## 一、先看完成度

```bash
npm run check:i18n          # 汇总：还剩多少条没搬
npm run check:i18n -- --list  # 明细：每处在哪一行
```

---

## 二、⚠️ 绝对不能动的（动了会坏功能）

| 类别 | 例子 | 为什么 |
|---|---|---|
| **命令行输出解析** | `src/vcs/svn.ts` 的 `CN_MAP`（`已更新: ['updated','U']`）、`parseUpdateFiles` 里的 `/^(已更新\|已添加\|…)/`、`/没有完全合并\|not fully merged/` | 这些是**解析 svn/git 命令输出**的匹配表，不是界面文案。改了直接导致状态识别失效 |
| **正则/映射表里的中文** | 任何 `match(/中文/)`、`{ 中文: 值 }` 形式的**解析用**表 | 同上。**判断标准：这段中文是给程序看的还是给人看的？** |
| **代码注释** | `// 打不开（目录已删）：标为失效` | 注释是给开发者看的，不翻译 |
| **传给系统命令的字符串** | `run('svn', ['commit', '-m', …])` 里的参数 | 命令参数不是界面文案 |
| **localStorage / CSS / data-\* 标识** | `localStorage.getItem('svngit-theme')`、`className="ctx-menu"`、`data-menu-key` | 是标识符，不是文案 |

拿不准就在该行**上一行**加 `// i18n-ignore` 注释并说明理由 —— 检查脚本会跳过整行，
后来人也能看懂"这里是故意留的"。

## 三、怎么改

### 导入

```ts
import { t } from '../../shared/i18n/index.js';   // 路径按文件位置调整（深一层多一个 ../）
```

`t` 是纯函数，**不需要 props 传递**。语言变了整树重渲染（App 顶层订阅，见 `client/shared/use-lang.ts`）。

### 各种场景

```tsx
// 1. JSX 文本
<button>提交</button>                    →  <button>{t('ops.commit')}</button>

// 2. 属性（字符串 → 表达式）
title="提交"                             →  title={t('ops.commit')}

// 3. 字符串字面量
showToast('已保存');                     →  showToast(t('common.saved'))

// 4. 插值：语序不同的语言也能各自成句
`已还原 ${n} 项`                         →  t('ops.reverted', { n })
//   语言包： zh '已还原 {n} 项'   en 'Reverted {n} item|Reverted {n} items'
//   ⚠️ `|` 是单复数分隔符（t() 按 params.n 选，n===1 取前段），中文包不写 `|`

// 5. 条件拼接：**拆成多个 key**，不要用字符串相加（英文语序不同，加不出来）
`更新了 ${n} 个文件${rev ? `，当前版本 r${rev}` : ''}`
  →  rev ? t('ops.updatedRev', { n, rev }) : t('ops.updated', { n })

// 6. 含 JSX 的标签（如带计数高亮）不能塞进 t()：把结构留在 JSX 里，只把文本取出来
label: <>解决冲突 (<span>{n}</span>)</>  →  <>{t('ops.conflicts')} (<span>{n}</span>)</>
```

### key 命名

- **前缀 = 域**，与语言包文件名一致（`look.` / `fs.` / `ops.` / `srv.` / `vcs.` …）
- 语义化：`ops.commit` 而不是 `ops.text12`
- **先查有没有现成的**：`src/shared/i18n/zh/common.ts` 已有通用动作词（确定/取消/保存…），别重复造

## 四、要产出什么

1. **改业务文件**：中文 → `t('key')`
2. **同时更新你这一对语言包**：`src/shared/i18n/zh/<域>.ts` 和 `en/<域>.ts`
   - 中文那条就是原文
   - 英文那条给出初翻（术语拿不准就保守直译，用户会统一校对）
   - **只改你自己的域**，别碰别的域、别碰 `index.ts`
3. 改完**自检**：

```bash
npx tsc --noEmit && npx tsc -p tsconfig.web.json --noEmit   # 类型 + 漏翻（en 漏了会报错）
npm run lint                                                # 0 error
npm run check:i18n                                          # 你这一域的数字应下降
```

### 英文的注意点

- **术语统一**：提交=Commit、更新=Update、还原=Revert、检出=Checkout、版本库=Repository、
  工作副本=Working Copy、冲突=Conflict、暂存=Stage、忽略=Ignore、标签=Tag、分支=Branch
- **英文比中文长 20-30%**：按钮、tab、表格列宽会撑破 —— 遇到明显会溢出的地方（如按钮文字）
  用更短的词（`确定`→`OK` 而不是 `Confirm`），并在回报里提一句
- 句子里的人称/语序按英文习惯写，**不要逐字直译**

## 五、域与文件的对应

| 语言包域 | 对应源码 | 说明 |
|---|---|---|
| `common` | `client/shared/`、`src/shared/` | 通用动作词 + 网络错误等应用级消息 |
| `look` | `client/appearance/` | 主题气泡 / 字体设置 |
| `ui` | `client/ui/` | 徽章 / 右键菜单 / 提示框 |
| `fs` | `client/filesystem/` | 列表 / 树 / 网格 / 预览 / 上传 / 忽略 |
| `ops` | `client/ops/` | 提交 / 更新 / 还原 / 标签 / Stash / 分支 |
| `repo` | `client/repo/` | 打开 / 新建 / 检出 / 登录 / 最近项目 |
| `hist` | `client/history/` | 提交列表 / 差异视图 |
| `conflict` | `client/conflicts/` | 三方冲突解决器 |
| `term` | `client/terminal/` | 终端 |
| `srv` | `src/server/`、`src/config.ts` | **HTTP 返回给界面的消息**（经 `api.ts` 直接透传，必须跟界面同语言） |
| `vcs` | `src/vcs/` | **操作结果消息**（⚠️ 解析命令行输出的中文不属此列） |
| `plat` | `src/platform/` | 打开方式 / 系统菜单集成 |
| `main` | `src/main/` | 窗口标题 / 系统对话框 / 启动日志 |
